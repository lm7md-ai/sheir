# معمارية نظام ديوان (Diwan Architecture & Dependency Graph)

تعتمد معمارية تطبيق **ديوان (Diwan)** على مبادئ المعمارية النظيفة القائمة على الميزات (Feature-First Clean Architecture)، مع عزل حاسم لمنطق المعالجة اللغوية والعروضية والتكرار المتباعد داخل حزمة Dart نقية ومستقلة (`diwan_core`).

---

## ١. مخطط التبعيات العام (Dependency Graph)

```
┌─────────────────────────────────────────────────────────────┐
│                 حزمة التطبيق (app/lib)                      │
│                                                             │
│   ┌─────────────────────────────────────────────────────┐   │
│   │   طبقة العرض (presentation: Widgets & Providers)    │   │
│   └──────────────────────────┬──────────────────────────┘   │
│                              │ يستهلك ويعتمد على            │
│                              ▼                              │
│   ┌─────────────────────────────────────────────────────┐   │
│   │   طبقة النطاق (domain: Entities, Repositories, UCs) │   │
│   │   (Pure Dart — خالية تماماً من حزم Flutter)          │   │
│   └──────────────────────────▲──────────────────────────┘   │
│                              │ ينفّذ واجهاتها                │
│                              │                              │
│   ┌──────────────────────────┴──────────────────────────┐   │
│   │   طبقة البيانات (data: Drift DAOs & Repositories)   │   │
│   └─────────────────────────────────────────────────────┘   │
└──────────────────────────────┬──────────────────────────────┘
                               │ يعتمد على
                               ▼
┌─────────────────────────────────────────────────────────────┐
│            الحزمة المستقلة (packages/diwan_core)            │
│  • ArabicNormalizer (معالجة الهمزات والتشكيل واللهجات)        │
│  • ArudEngine (كشف بحور الخليل والتقطيع العروضي)            │
│  • RecitationAlignmentEngine (خوارزمية Needleman-Wunsch)    │
│  • SpacedRepetitionEngine (خوارزمية FSRS / SM-2)            │
│  • ClozeGenerator (نظام الإخفاء التدريجي)                   │
└─────────────────────────────────────────────────────────────┘
```

## ٢. قواعد الحدود المعمارية الصارمة (Strict Boundary Rules)

1. **طبقة النطاق (domain)**:
   - تتضمن الكيانات (`Entities`)، واجهات المستودعات (`Repository Interfaces`)، وحالات الاستخدام (`UseCases`).
   - كود Dart نقي بنسبة 100%؛ **يُحظر منعاً باتاً** استيراد أي ملف من مكتبة Flutter (`package:flutter/...`).

2. **طبقة العرض (presentation)**:
   - تتضمن عناصر الواجهة (`Widgets`) وموفري الحالة (`Riverpod Notifiers`).
   - **يُحظر منعاً باتاً** استيراد طبقة البيانات (`data`) مباشرة من داخل الواجهات. التواصل يتم حصرياً عبر واجهات الـ domain وحالات الاستخدام.

3. **حزمة النواة (diwan_core)**:
   - حزمة Dart مستقلة في مسار `/app/packages/diwan_core`.
   - تغطية اختبارات أحادية تفوق 90% مع نصوص شعرية واقعية محققة.
   - لا تعتمد على أي مكتبة خارجية للواجهات.

4. **الفصل التام لقواعد البيانات**:
   - `poems.db`: مكتبة الشعر المقروءة فقط والمفهرسة بـ FTS5.
   - `user.db`: قاعدة بيانات تقدم المستخدم واستذكاره المتباعد، مع ربط ثابت بالمعرفات النصية المستقرة (`poem_uid` و `verse_uid`) دون مفاتيح أجنبية عبر الملفات.

## ٣. أداة التحقق الآلي في خط البناء (Automated Architecture Linter)
يتم التحقق من سلامة هذه القواعد آلياً في كل عملية بناء وفحص عبر:
- أداة `scripts/check_clean_architecture.py`.
- اختبار دارت `app/test/architecture/clean_architecture_lint_test.dart`.
- خط سير العمل في GitHub Actions `.github/workflows/ci.yml`.
